# XposedSmsCode 2.5.3

由 Oldcucumber 维护的 legacy-APIupdate fork。应用版本与发布标签统一为 2.5.3，
versionCode 升至 54；继续使用原包名和 fork 发布签名，可覆盖安装同签名旧版。

## 默认提取规则

- 收紧外语关键词的单词边界，减少 Mate、DuMate、CodeGeeX 等商品名称触发误识别。
- 默认提取忽略 http(s) / www 链接中的关键词和数字，避免问卷 code 参数被误识别。
- 补充登录码、登陆码、登錄碼、一次性密码／密碼／口令，以及大小写混合的 code、OTP。
  新增中文格式只提取标签紧随的 4–8 位字母数字码，避免交易序号、日期抢占八位验证码。
- 自定义公司／关键词／正则规则仍最先匹配原始短信；用户自行编辑的关键词正则保持原语义。
  原样保存的旧默认关键词在解析时使用新默认，不覆盖配置文件。
- 保留已有关键词的候选评分、纯字母验证码、空格验证码与规则顺序。

本地对 9,484 条存量收件短信进行前后对比：12 条已核实的误识别不再提取，
新增正确提取 4 条一次性密码短信，其余 9,468 条结果一致。
这是单设备存量样本对比，不是通用准确率；已删除或拦截的短信未包含在内。
回归用例采用虚构号码与模板，未将原始短信、验证码、数据库或个人记录提交到仓库。
通用场景测试来自人工构造，不代表访问或验证过模型训练数据。

仍可能误识别包含验证码字样的反诈、上行激活、登录通知等短信；本版不增加宽泛的
整条短信排除规则，以免吞掉同时包含真实验证码和风险提示的短信。

## API 102 与兼容性修复汇总

- 补充现代框架的 system 作用域，保留 android 与电话作用域。
- 接入 API 102 模块日志，记录 Hook 安装、系统构建及远程配置加载状态。
- 构造器初始化缺失时尝试在短信分发阶段恢复 Context；通知与复制接收器初始化可独立重试。
- 包含 greenDAO 反射类、Retrofit 泛型与 Gson 实体混淆保留修复，以及删除旧入口后的启动修复。
- Release 构建执行单元测试、校验签名和 APK 版本，并使用触发提交创建对应标签。

界面、开关及正常操作流程不变。未知签名、配置不可用或解析失败仍放行原短信。
澎湃 OS 4 尚无真机验证，不能据此宣称完整支持，详见 [兼容性排查](hyperos-compatibility.md)。
完整 Lint 的历史问题未在本版全部清除。

升级后请确认系统框架与电话作用域，重启并打开模块应用同步配置，再测试验证码短信。
